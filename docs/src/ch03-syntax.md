# 言語の構文

プログラミング言語を定義する最初の一歩は、**プログラムをデータとして表す**ことです。文字列としてのソースコードではなく、構造を持った木——**抽象構文木（AST）**——として表します。Lean 4 ではこれが `inductive` 一発で書けます。

## 型

Simplean の型は三種類です。

```lean
{{#include ../../Simplean/Syntax.lean:ty}}
```

`list` は要素型を引数に取るので、`Ty.list Ty.int`（整数のリスト）、`Ty.list (Ty.list Ty.int)`（整数のリストのリスト）のように入れ子にできます。`List[T]` の `T` に当たるのが `elem` です。

## 演算子

式に出てくる演算子を、単項と二項に分けて列挙します。

```lean
{{#include ../../Simplean/Syntax.lean:ops}}
```

- 単項：符号反転 `neg`、論理否定 `not`、リストの `head`/`tail`/`isNil`/`len`、文字列長 `strLen`、整数の文字列化 `toStr`
- 二項：四則と剰余、比較 `lt`/`le`/`eq`、論理 `and`/`or`、文字列連結 `concat`、リスト構築 `cons`

演算子の**型**（どんな型の引数を取り、何を返すか）と**意味**（値をどう計算するか）は、ここでは決めません。第 5 章と第 6 章で `unopTy`/`binopTy` と `applyUn`/`applyBin` として与えます。構文はあくまで「形」だけです。

## 式

```lean
{{#include ../../Simplean/Syntax.lean:expr}}
```

| コンストラクタ | 意味 | 例 |
|---|---|---|
| `lit n` | 整数リテラル | `.lit 42` |
| `strLit s` | 文字列リテラル | `.strLit "hi"` |
| `var x` | 変数参照 | `.var "n"` |
| `nil elem` | 要素型 `elem` の空リスト | `.nil .int` |
| `unop op e` | 単項演算 | `.unop .not (.var "b")` |
| `binop op e₁ e₂` | 二項演算 | `.binop .add (.lit 1) (.lit 2)` |
| `call f args` | 関数呼び出し | `.call "fact" [.lit 10]` |

**`nil` が要素型を持つ**のは、型検査で「この空リストは何のリストか」を迷わないためです。Scala で `List.empty[Int]` と書くのと同じ理由です。

**`call` の引数が `List Expr`** であることに注目してください。`Expr` の定義の中で `List Expr` を使っています。このような型を**入れ子の帰納型（nested inductive）**と呼びます。Lean 4 はこれを扱えますが、いくつか制約があります。

- `deriving DecidableEq` が使えません（`Repr` だけ導出しています）
- `induction e` という tactic がそのまま使えません

この本の証明では、式の構造ではなく **fuel に関する帰納法**を使うので、二つ目の制約は問題になりません。これは設計上の重要な選択で、第 9 章で振り返ります。

## 文

```lean
{{#include ../../Simplean/Syntax.lean:stmt}}
```

| コンストラクタ | 意味 |
|---|---|
| `skip` | 何もしない |
| `decl x t e` | 変数 `x : t` を宣言し、`e` の値で初期化 |
| `assign x e` | 既存の変数 `x` に `e` の値を代入 |
| `seq s₁ s₂` | `s₁` のあと `s₂` |
| `ite c s₁ s₂` | `c` が真なら `s₁`、偽なら `s₂` |
| `while c body` | `c` が真の間 `body` を繰り返す |

条件 `c` は **`Int` 型の式**で、`0` が偽、それ以外が真です。Simplean には `Bool` 型がないので、C 言語と同じ流儀を採っています（`Bool` 型を足すのは第 14 章の演習です）。

`decl`（宣言）と `assign`（代入）を分けているのは型検査のためです。実行時の振る舞いは同じ「環境の更新」ですが、宣言は「新しい名前を型つきで導入する」、代入は「既にある名前に同じ型の値を入れる」という異なる型付け規則を持ちます（第 5 章）。

## 関数とプログラム

```lean
{{#include ../../Simplean/Syntax.lean:fundef}}
```

関数は、名前・引数（名前と型の組のリスト）・戻り型・**本体の文**・**結果の式**から成ります。「本体の文を実行してから、結果の式を評価して返す」という形で、途中で `return` する構文はありません。制御の流れが一本道になるので、意味論と VM の両方が単純になります。

プログラムは、関数定義の列と、空の環境で評価する `main` 式です。関数は再帰呼び出しも相互再帰もできます（第 6 章の `isEven`/`isOdd`）。

## 例：階乗

AST を直接書くと、たとえば階乗はこうなります。

```lean
{{#include ../../Simplean/Examples.lean:fact}}
```

これは次の疑似コードに対応します。

```text
fn fact(n: Int): Int {
  let r: Int = 1;
  while 0 < n {
    r := r * n;
    n := n - 1;
  }
  r
}
main = fact(10)
```

AST は人間が読み書きするには冗長ですが、**プログラムを扱うプログラム**（型検査器・インタプリタ・コンパイラ）にとっては最も扱いやすい形です。この本ではパーサ（文字列から AST への変換）は作りません。パーサは証明の対象として面白い部分ではなく、AST から始めれば言語処理系の本質に集中できるからです。

## 設計の選択を振り返る

この章で決めたことのうち、後の証明に影響するものをまとめます。

- 条件は `Int`：`Bool` 型が無いぶん、型と値のケースが一つ減ります
- `nil` に要素型：型検査が式の形だけで決まります（型推論が要りません）
- `return` 無し：意味論の結果の型が「環境」か「値」かの二通りで済みます
- 引数は `List Expr`：入れ子の帰納型になりますが、fuel 帰納法で回避します

次の章では、実行時の**値**と、値が型を持つという関係 `HasType` を定義します。
